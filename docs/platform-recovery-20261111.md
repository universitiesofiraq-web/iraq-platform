# تقرير إصلاح تعطل المنصة

تاريخ المراجعة 11 نوفمبر 2026 بتوقيت بغداد.

## النتيجة

الإصلاحات محفوظة على الفرع `fix/platform-data-loading-20261111` المبني على أحدث `main` وقت الفحص، بالتعديل `c74d359fc948a1e9a07cb1ea885dc1eb1a4f65e8`.

## السبب الذي ثبت من Cloudflare

رفضت قاعدة الإنتاج حتى استعلام قراءة صغير بسبب تجاوز الحد اليومي لقراءة الصفوف في D1 المجانية. عرضت إحصاءات آخر 24 ساعة نحو 19 مليون صف مقروء. استعلام جلب أقسام كلية محددة نُفّذ 4,437 مرة وقرأ نحو 16.92 مليون صف. كان البحث العام في إدارة التعيينات يطلق طلبات منفصلة للكليات والأقسام في كل جامعة، دون فهرس مناسب لربط القسم بكليته.

سبق أن طُرح احتمال ارتباط الاختفاء بتفعيل الجامعات. نفاد حصة D1 هو العطل الذي تأكد مباشرة في هذه المراجعة. مراجعة حالة كل جامعة ووجود جميع صفوفها تتطلب عودة استعلامات الإنتاج.

## التعديلات المنفذة

- ترحيل إضافي `0017_catalog_read_indexes.sql` ينشئ فهارس للربط بين الأقسام والكليات، والمحاضرات والمواد، وعدّ رسائل الدردشة غير المقروءة. يحافظ على الصفوف الحالية.
- تجميع تحميل شجرة الجامعة من إدارة التعيينات في طلب واحد. البحث عبر الجامعات يعيد استخدام دليل مجمّع، مع توحيد الطلبات المتزامنة.
- تخزين مؤقت لمدة دقيقة لبيانات البحث العامة داخل العامل. يعاد فحص ظهور الجامعات في كل طلب، ويُمسح المخزن المحلي عند تعديل الدليل. تبقى بيانات الصلاحيات والحسابات خارج هذا المخزن. قد تحتاج أسماء الكليات والأقسام المعدلة في عامل آخر إلى دقيقة لتنعكس في فهرس البحث.
- إرجاع أخطاء الخدمة برموز واضحة وحالة 503 عند نفاد الحصة، وحجب تفاصيل الخادم عن المستخدمين.
- الفصل بين البيانات الفارغة وفشل جلب البيانات في الرئيسية والجامعات والتسجيل والقسم والمادة والمرحلة ومنصة الطالب.
- الحفاظ على القسم والمرحلة المحفوظين أثناء تعطل الخادم، وإضافة إعادة المحاولة والعودة إلى الجامعات.
- رفض الاستجابات القديمة عند تبديل الجامعة أو الكلية بسرعة في صفحة الرفع. تتصفّر الاختيارات التابعة، ويستعيد زر الرفع حالته بعد انقطاع الطلب.
- عرض خطأ الحساب الحقيقي وخيار إعادة المحاولة في الإدارة والدردشة والتمثيل الطلابي.
- تقليل متابعة رسائل الدردشة إلى مرة كل عشر ثوان، وتحديث قائمة الغرف كل ثلاثين ثانية، مع إيقاف المتابعة في الخلفية والتراجع التدريجي عند الفشل.
- تصحيح تعارض CSS مع السمة `hidden` الذي كان يكشف نماذج مخفية قبل اكتمال التحقق من الحساب.
- إظهار اختصار آخر قسم بعد التحقق من وجوده في نتائج الدليل الفعلية.
- استبدال عنوان صفحة الكورس المخصص للطب بعنوان مناسب لجميع التخصصات.

## الاختبارات

اجتاز الأمر التالي 61 حالة في مشغّل اختبارات Node، ويشمل الاختبارات القائمة وسبعة اختبارات إضافية لهذه المشكلات.

```bash
node --test iraq-platform/tests/*.test.mjs tests/*.test.cjs
```

شملت الفحوص عزل جامعتين، والصلاحيات، وتفعيل الجامعة وتعليقها، وتبديل الاختيارات أثناء تأخر الاستجابة، والحفاظ على الاختيارات عند نفاد الحصة، وحجب الأخطاء الداخلية، وترحيلات قاعدة قديمة دون فقد صفوفها. أكد `EXPLAIN QUERY PLAN` استخدام `idx_departments_college` للاستعلام الذي ظهر في Cloudflare بدل مسح جدول الأقسام. فُحصت صياغة 33 سكربتًا مضمنًا في HTML، واجتاز `git diff --check`.

تعذر تشغيل Chromium المحلي بسبب قيود تشغيل المتصفح في بيئة التنفيذ. لذلك تظل المعاينة المرئية للإصلاح، وعرض الهاتف، وتسجيل Google والرفع وفتح PDF على Pages بحاجة إلى تحقق بعد تجهيز المعاينة وعودة الخدمة.

## الوظائف التي استُخدمت كما هي

استُخدم نظام الجلسات الحالي، والتحقق الهرمي من الصلاحيات على الخادم، ومسارات رفع الملفات الحالية، وقارئ PDF. أثبتت الاختبارات القائمة استمرار عزل نطاقات الممثلين والرافعين. استُبقي مسار اعتماد الجامعات وتفعيلها، ولم تُفعّل الجامعات بالجملة.

## حالة النشر والحفظ

ثلاث نقاط حفظ برمجية أُنشئت خلال الإصلاح. فشلت المحاولة البرمجية الأولى للرفع بسبب غياب بيانات دخول Git ورفض اتصال GitHub الكتابة بحالة 403. بعد طلب المالك الرفع، أُنشئ الفرع ورُفعت الملفات من حسابه المفتوح عبر محرر GitHub داخل المستودع. أُعيد جلب الفرع وتأكد تطابق الملفات البرمجية الثلاثين مع النسخة المحلية المختبرة. أُرفق هذا التقرير ليصبح إجمالي الملفات المعدلة 31 ملفًا. قاعدة الإنتاج ما زالت تحتاج إلى استعادة حصة D1 وإجراءات النشر المعتمدة، لذلك لم تُستكمل مراجعة عدد الجامعات أو محتوياتها على الإنتاج.

تحتوي حزمة `platform-repair-checkpoint.bundle` على الفرع وسجل الاستعادة الكامل. لاستيرادها داخل نسخة المشروع المرتبطة بحساب GitHub يملك الكتابة، استخدم المسار الفعلي للحزمة.

```bash
git fetch /path/to/platform-repair-checkpoint.bundle refs/heads/fix/platform-data-loading-20261111:refs/heads/fix/platform-data-loading-20261111
git switch fix/platform-data-loading-20261111
git push -u origin fix/platform-data-loading-20261111
```

الفرع المرفوع متاح على `https://github.com/universitiesofiraq-web/iraq-platform/tree/fix/platform-data-loading-20261111`. التسليم الحالي هو إصلاح على فرع مستقل. نشر الإنتاج يظل خاضعًا لموافقة المالك السابقة. يحتاج تطبيق الترحيل الجديد إلى قاعدة تستطيع تنفيذ الاستعلامات. وفق رسالة Cloudflare، يتجدد حد الاستخدام عند منتصف الليل UTC، أي الثالثة صباحًا بتوقيت بغداد، أو يمكن للمالك اختيار ترقية Workers المدفوعة. يلزم التحقق من D1 ومراجعة الجامعات المشاركة بعد عودة الخدمة وقبل اعتماد النشر.

## مواءمة تحديثات main

جُمعت إصلاحات الفرع مع تحديث `817a256` من `main`. حُلّت أربعة تعارضات في الدليل، والترحيلات المولدة، والمساعد، وواجهة الدردشة. استُبقيت إضافات حذف الحساب، وترحيل قائمة الملفات إلى D1، والتحقق من العضوية، وحماية ملفات PDF، وضبط الحصص الذرية.

نُقل ترحيل فهارس الإصلاح إلى `0020_catalog_read_indexes.sql` حتى يأتي بعد ترحيلات `0017_hardening` و`0018_upload_manifest` و`0019_more_indexes`. أسماء الفهارس متوافقة وتُنشأ بشرط `IF NOT EXISTS`.

التخزين المؤقت المشترك يقتصر على قوائم الدليل العامة لمدة خمس دقائق، مع فحص الجامعات النشطة قبل استخدامه. ردود تفاصيل القسم والمادة التي تتضمن صلاحيات الحساب تُجلب مباشرة. تبقى متابعة الدردشة كل 15 ثانية، مع التراجع التدريجي عند تعطل الخدمة.

اجتاز التحقق النهائي 70 حالة، بما فيها منع خلط صلاحيات حسابين في الكاش، واحترام تعليق الجامعة فورًا، وحذف الحساب، وترحيل قائمة الملفات، وفحوص PDF الجديدة. تُرفع المواءمة إلى فرع الإصلاح المرتبط بطلب الدمج رقم 12. يبقى اعتماد النشر على الإنتاج للمالك.
